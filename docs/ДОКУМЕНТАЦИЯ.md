## 1. Обзор системы

MyAstro -- сервис персонализированных AI-гороскопов. Генерирует ежедневные гороскопы на основе профиля пользователя, его интересов и истории обратной связи.

**Каналы:** веб-интерфейс (SPA) + мобильное приложение (Flutter, планируется) + Telegram-бот

**Стек:** Python 3.12 / FastAPI / PostgreSQL 16 / Redis 7 / OpenRouter (AI) / Docker Compose

---

## 2. Архитектура

```
Клиент (Mobile/Bot)
       |
    Nginx :80
       |
  FastAPI :8000
       |
  +-----------+-----------+
  |           |           |
PostgreSQL  Redis     OpenRouter
(данные)   (кеш,     (AI-генерация)
           лимиты)
```

**Потоки данных:**
- Клиент -> API: только предопределенные параметры (нет свободного ввода текста)
- API -> БД: PII зашифрованы (AES-256), поиск по хешам
- API -> AI: промпт формируется на сервере из данных БД
- AI -> API -> Клиент: ответ проходит фильтр безопасности контента

## 4. Аутентификация

**Принцип:** в БД не хранятся никакие пароли, токены или хеши аутентификации. Только внешние ID провайдеров (telegram_id, google_id).

**Поток:**
1. Клиент авторизуется через Telegram Login или Google Sign-In
2. Сервер верифицирует подпись провайдера
3. Сервер выдает JWT-пару: access token (15 мин) + refresh token (30 дней)
4. Каждый запрос к API содержит: `Authorization: Bearer {access_token}`

**JWT содержит:** user_id, тип токена, уникальный ID для отзыва (jti)

**Refresh:** `POST /auth/refresh` с refresh_token -> новая пара токенов

Базовый URL: `http://{host}/api/v1`

Заголовок авторизации: `Authorization: Bearer {access_token}`

```json
    "name": "Иван",
    "birth_date": "1995-03-15",
```

### Реклама (бесплатные пользователи)

#### Поток:
1. `POST /ads/request-token` -> получаем токен
2. Клиент показывает AdMob Rewarded Video
3. `POST /ads/confirm {"token": "..."}` -> подтверждаем просмотр
4. `POST /horoscope/generate` -> генерируем (токен проверяется на сервере)

### Гороскопы

#### POST /horoscope/generate

Генерация гороскопа. Пользователь НЕ вводит текст -- только выбирает параметры.

**Запрос (общий гороскоп):**
```json
{}
```

**Запрос (фокусный, на тему любви):**
```json
{
  "horoscope_type": "focused",
  "focus_interest_id": "love"
}
```

**Запрос (для члена семьи):**
```json
{
  "family_member_id": "uuid-here",
  "horoscope_type": "general"
}
```

**Запрос (пересоздание):**
```json
{
  "horoscope_type": "regeneration"
}
```

**Ответ (200):**
```json
{
  "id": "h1g2f3e4-...",
  "horoscope_date": "2026-04-28",
  "horoscope_text": "Дорогой Иван, сегодня Рыбы ощущают особый прилив энергии...",
  "ai_model_used": "openai/gpt-4o-mini",
```

- 402: Нужно посмотреть рекламу (бесплатный тариф)

## 7. Как работает генерация гороскопа

### Структура промпта

Промпт состоит из 3 частей. Пользователь не влияет ни на одну из них напрямую.

#### Часть 1: Системный промпт (постоянный)

```
Ты - опытный астролог с глубоким знанием астрологии.
Ты создаешь персонализированные, вдохновляющие гороскопы на русском языке.

Правила:
- Пиши на русском языке
- Гороскоп должен быть конкретным и применимым к жизни человека
- Длина: 150-250 слов
- Тон: теплый, мудрый, вдохновляющий, но не наивный
- Включай конкретные советы на день
- Не используй клише и общие фразы
- Учитывай обратную связь пользователя

КРИТИЧЕСКИ ВАЖНЫЕ ОГРАНИЧЕНИЯ:
- НИКОГДА не упоминай суицид, самоповреждение или смерть
- НИКОГДА не предлагай преступные действия или насилие
- НИКОГДА не унижай пользователя
- НИКОГДА не давай конкретных медицинских рекомендаций
- НИКОГДА не давай конкретных финансовых рекомендаций
- Тон всегда позитивный и поддерживающий
```

#### Часть 2: Контекст пользователя (из БД, расшифровывается на сервере)

```
Знак зодиака: Рыбы
Стихия: Вода
Качество: Мутабельный
Пол: male
Имя: Иван
Время рождения: 14:30
Место рождения: Москва
Профессия: Дизайнер
Интересующие сферы жизни: романтические отношения, любовь, партнерство;
  карьера, профессиональный рост, рабочие проекты
```

Обрати внимание: интересы приходят не как "love, career", а как развернутые описания из каталога (`prompt_hint`). Это дает AI больше контекста.

#### Часть 3: История с обратной связью (из БД)

```
Предыдущие гороскопы и обратная связь:

--- Гороскоп от 2026-04-27 [ПОНРАВИЛОСЬ пользователю] ---
Дорогой Иван, сегодня звезды указывают на то, что в сфере карьеры
тебя ждет неожиданный поворот...

--- Гороскоп от 2026-04-26 [НЕ ПОНРАВИЛОСЬ пользователю] ---
Рыбы сегодня могут почувствовать себя немного потерянными...
```

#### Итоговый промпт (отправляется в AI)

```
Составь персональный гороскоп на 28.04.2026 для этого человека:

[Контекст пользователя - см. выше]

[История - см. выше]

Учти обратную связь по предыдущим гороскопам. Если что-то не понравилось -
измени стиль и подход. Если понравилось - сохрани тон, но предложи свежее
содержание.
```

### Цепочка обработки

```
1. Клиент: POST /horoscope/generate
        |
2. Проверка рекламы (free) / лимитов (plus/premium)
        |
3. Загрузка профиля из БД, расшифровка PII
        |
4. Загрузка истории (2/3/5 последних в зависимости от тарифа)
        |
5. Формирование промпта на сервере
        |
6. Отправка в AI (OpenRouter -> выбранная модель)
        |
7. Проверка безопасности контента (regex-фильтр)
        |
   7a. Если не прошел -> повторная генерация с напоминанием
   7b. Если повторная тоже не прошла -> безопасный fallback-текст
        |
8. Сохранение в БД + кеш в Redis
        |
9. Инвалидация рекламного токена (free)
        |
10. Ответ клиенту
```

### Тестирование качества гороскопов

При `DEBUG=true` доступны эндпоинты:

- `GET /debug/config` -- текущие модели и настройки
- `POST /debug/prompt-preview` -- увидеть точный промпт для тестового профиля
- `POST /debug/test-generate` -- сгенерировать тестовый гороскоп
- `POST /debug/safety-check` -- проверить текст через фильтр безопасности

**Пример prompt-preview:**

```json
POST /api/v1/debug/prompt-preview
{
  "zodiac_sign": "Рыбы",
  "gender": "male",
  "name": "Иван",
  "interests": ["love", "career", "health"],
  "birth_place": "Москва",
  "profession": "Дизайнер"
}
```

Ответ покажет точный system_prompt и user_prompt, которые будут отправлены в AI.

## 8. Безопасность

### Защита данных

| Данные | Метод защиты |
|---|---|
| Имя, email, место рождения, профессия | AES-256 шифрование |
| Email для поиска | SHA-256 однонаправленный хеш |
| Пароли | Не хранятся (внешняя аутентификация) |
| JWT токены | Не хранятся, отзыв через Redis blacklist |

### IDOR-защита

Все эндпоинты, принимающие ID объектов, проверяют принадлежность текущему пользователю:
- `family_member_id` -> проверка `owner_id == current_user.id`
- `horoscope_id` -> проверка `user_id == current_user.id`
- Профиль всегда привязан к `current_user` из JWT

### Защита от инъекций в промпт

- Пользователь не вводит свободный текст в промпт
- Интересы выбираются из предопределенного каталога
- Все строковые данные проходят через `sanitize_for_prompt()`:
  - Обрезка по длине
  - Фильтрация паттернов инъекций ("ignore instructions", "system prompt" и т.д.)
  - Удаление управляющих символов

### Фильтр безопасности контента

Каждый сгенерированный гороскоп проверяется на:
- Суицид, самоповреждение
- Насилие, преступления
- Дискриминация, унижение
- Пропаганда наркотиков
- Опасные медицинские/финансовые советы

При обнаружении: автоматическая перегенерация или безопасный fallback.

### Rate Limiting

- Атомарный INCR в Redis (нет race conditions)
- При падении Redis -- запросы отклоняются (fail-closed)
- Отдельные счетчики для general / focused / regeneration
- TTL 24 часа для автоматического сброса
